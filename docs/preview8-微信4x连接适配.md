# preview8：微信4.x连接适配

日期：2026-11-08。

## 对照结果

在线确认用户指定的[lxw112190/Moect](https://github.com/lxw112190/Moect)当前main仍为 `3d08feceae6492fe2f4f9f8e03b02ec411970c90`，与此前记录相同。

其[wx4/key.py](https://github.com/lxw112190/Moect/blob/3d08feceae6492fe2f4f9f8e03b02ec411970c90/wx4/key.py)介绍较新4.1版本使用Config.Cipher对象：查找配置名称与引用，取配置blob、掩码还原字面量，再通过数据库第一页HMAC认证。4.0路径扫描raw-key字面量，部分候选需要派生。本项目先前已独立实现这些路径及合成回归，并在preview5的4.0.5.16账号验证过读取；本次发现主要的阻挡是版本检查写死4.0.5.16。

Moect的[README](https://github.com/lxw112190/Moect/blob/3d08feceae6492fe2f4f9f8e03b02ec411970c90/README.md)也明确面向Windows微信4.x，但没有承诺覆盖全部4.x版本。两套工具仍可能因布局、字段、本机缓存和读取限额产生不同结果。

## 修改

- 允许Windows x64 Weixin.exe/WeChat.exe的4.*.*.*文件版本进入同一认证流程。其他主版本、无关进程、缺失或非法文件版本仍拒绝内存读取。
- 文件版本固定结构检查补齐长度、空指针和签名，防止把无效版本资源当成合法版本。
- 界面和错误提示统一为“微信4.x”，记录本次实际版本。self-test与version.json分别报告目标范围4.x和既有实测4.0.5.16。本轮real_account_verified仍为false。
- 保留raw-key、Config.Cipher、受限派生、页认证、WAL验证、所选账号与PID、120秒/2GiB和候选数量限制。不复制Moect代码、不改变原件、不扩大自动读取范围。
- 完整模型、DirectML和语音识别命名流程保持现有打包方式。

## 验证边界

新增4.0/4.1/其他4.x版本号与进程名矩阵、非4.x/无效资源拒绝、同账号raw与配置路径共同命中回归。现有配置对象、跨块、错误指针、错误账号、派生限额、取消、WAL、语音转换、导出和窗体检查继续执行。

使用合成账号验收，不读取当前运行的真实微信或私人语音。允许尝试4.x不等于所有4.x实测通过；新的具体版本应在用户选定账号后用实际连接/导出结果记录。
