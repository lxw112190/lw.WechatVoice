# preview18：有效页、空闲页与 WAL 兼容修复

2026-11-10。用户的 preview17 截图明确报告主库第 8454 页 `PAGE_AUTH_FAILED`。这说明密钥已通过首页认证，但旧版在检查后续主库页时中止；**截图本身不能确认第 8454 页的实际用途**。

本次在合成数据库上复现并修复了三类旧版误拒绝。不是关闭页认证，也不宣称已经在该真实账号上验收。

## 已修复的判断

1. **主库旧页被已提交 WAL 覆盖**。按照 [SQLite 读取规则](https://sqlite.org/fileformat.html#reader_algorithm)，最新有效已提交 WAL 页优先。现在先完整验证冻结 WAL 的头、帧 checksum、加密页认证、代际及提交边界，再把已提交密文合并到私有冻结主库，随后认证/解密最终有效页。旧主库页已被有效替代时不会再误阻止读取；未提交替换、坏 HMAC、坏 checksum 仍拒绝。
2. **已确认的空闲叶页**。按 [SQLite 空闲页格式](https://sqlite.org/fileformat.html#the_freelist)，空闲叶页不承载数据。先认证首页，再认证整个空闲链主节点，校验页号范围、重复/循环和总数；只有链中明确列出的叶页才输出为零页。活动页、空闲链主节点仍认证，最终完整性检查必须通过。伪造分配把活动页标成空闲的用例仍被拒绝。
3. **物理预分配尾部**。仅当已认证首页的页数有效且变更计数匹配时，使用其逻辑大小；WAL 有提交时以验证后的提交大小为准，符合 [SQLite 页数规则](https://sqlite.org/fileformat.html#in_header_database_size)。失效计数不能用来静默裁掉认证失败页。

所有合并、清零和裁切都发生在本工具生成的私有副本上，原库/WAL 仍只读。C# 和 Python 参考实现同步更新；部署仍为 C# + 原生库，不加入 Python 运行时。

## 实证与回归

使用实际 preview17 引擎运行新增合成样本，复现 5 个原版误拒绝：有效 WAL 替换坏旧页、零/残留内容的空闲叶页、逻辑大小之外预分配页、WAL 提交后丢弃的旧尾部。新版接受这些有效样本，输出与 Python 参考逐字节一致。

快照对照扩展为 **29 组**，覆盖原有全部拒绝场景，以及：

- 有效已提交替换、最后提交版本优先、忽略未提交版本。
- 校验和有效但 HMAC 损坏的替换页仍拒绝；未提交页不能救回坏活动页。
- 空闲叶页内容可清零；坏主链、循环、越界/重复、活动零页仍拒绝。
- 验证过的空闲链错误指向活动根页时，最终 SQLite 检查仍拒绝发布。
- 有效逻辑页数的预分配尾部可排除，失效页数计数不能用于排除尾部。

除字节对照外，使用独立 SQLite 查询验证最新/未提交版本的实际字段值和清零空闲页后的活动行数。源文件写入共享被禁用的只读回归、取消、重试和隐私诊断继续运行。

另以 9024 页、9000 条活动记录的合成库验证跨越第 8454 页的认证与解密，C# 输出 SHA256 与 Python 参考一致。构建脚本现在在成功或失败时均清理经过路径验证的临时 ASR 副本，避免失败后留下重复模型；交付模型及 DirectML 保留。

## 使用与范围

直接用 preview18 连接同一账号测试。若仍认证失败，不会输出伪成功；诊断新增冻结映像的物理/逻辑页数、空闲叶页数量、首页声明页数及 WAL 提交页数，帮助判断剩余问题，仍不记录页内容、路径或密钥。

本轮使用合成数据库和既有错误截图，没有读取真实聊天、账号密钥或真实微信进程内存；第 8454 页属于哪一类，仍需真实复测结果确认。模型、DirectML 和 preview16 加速保留。
