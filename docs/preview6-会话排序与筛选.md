# preview6：会话排序与筛选

开发与验证：2026-11-07～2026-11-08。

左侧新增名称/账号搜索框、清空按钮、类型筛选、排序下拉框和显示数量/当前会话说明。默认按最近语音从新到旧。

- 搜索：会话显示名称与账号标识，忽略大小写，输入即筛选。
- 类型：全部、单聊/其他、群聊（账号以@chatroom结尾）。类型判断不把陌生人/服务号笼统宣称为好友。
- 排序：最近语音时间新/旧两个方向、名称正/倒序、语音数量多/少两个方向。数量是数值排序，时间取整个已读取会话的MAX(stamp)，不随当前语音分页变化；名称采用当前系统文化的比较规则，不宣称拼音搜索。相同值再按名称与账号稳定排序。
- 左侧筛选是导航，不是语音导出筛选。原选中会话独立保存，筛空不会改成全部会话，也不清掉右侧当前语音。当前会话名称持续显示；恢复条件后按账号标识恢复选中。进入导出页仍使用冻结会话/所选ID及该页面的日期条件。
- 更换来源、重新建立读取会话时清空旧联系人缓存和搜索；同一读取会话内分页、排序和搜索不重新读取微信进程/原始数据库，也不运行语音识别。

延续原有目录返回的会话清单范围，本轮未扩展账号读取、进程扫描、模型、语音文件格式或授权范围；没有重新读取真实聊天来做界面测试。

验证夹具包含三个合成会话（不同名称、数量与最近时间，含群聊）。核心测试检查COUNT/MIN/MAX聚合及分页/日期不污染会话统计。真实Application.Run界面回归检查六种排序、名称/账号搜索、单聊/群聊、零结果、清空恢复、当前会话/导出范围保持及最小窗口控件可见性，最后实际导出被选会话的三条WAV和manifest。证据位于忽略的test-results与交付目录gui-test中，截图仅含合成数据。

本轮38项核心测试通过，主窗体/导出窗体独立DesignSurface通过，正常消息循环下的上述会话筛选/排序、选中会话三条WAV导出与最小窗口控件边界检查通过。未重读真实微信进程或账号；preview5的真实账号连接记录作为历史验证保留，不当成本轮重新实测。
