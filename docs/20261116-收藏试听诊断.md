# 收藏试听失败诊断

本轮只分析用户提供的脱敏诊断包，没有读取真实账号数据库、语音或微信进程内存。

## 日志已经证明的内容

- 工具 1.1.0，Windows 10 x64；日志识别到微信 4.1.0.30。
- 普通语音读取成功 12593 条，6/6 数据库副本完成。
- 收藏模式读取成功 17 条语音，7/7 数据库副本完成，密钥匹配 7/7，列表查询成功；catalog_summary 有 1 项提示。
- 部分 preview 成功，失败调用栈均停在 Main → Execute → Preview → Payload，尚未进入语音解码。
- 用户确认失败提示为“收藏语音原件缺失”。因此这些失败是缺少可读取的收藏音频副本，而不是这份日志中的数据库认证失败或解码器加载失败。

旧日志没有记录缺失数量、扫描缓存情况和消息 ID 回退统计，不能从这份包判断具体是哪种未匹配原因；不能直接推断所有附件尚未下载，也不能承诺下载后一定恢复。

## 本轮改进

源码准备版本 1.1.1。加入以下不含账号信息的诊断字段：favorite_cache_present、favorite_cache_scanned、favorite_cache_hits、favorite_server_hits、favorite_missing、favorite_ambiguous、favorite_md5_rejected、favorite_no_server、favorite_cache_unreadable。两层白名单均保留这些字段，仍剔除文件路径、MD5、消息 ID、标题和正文。

新增错误码：FAVORITE_AUDIO_MISSING 表示副本文件不存在；FAVORITE_AUDIO_SIZE 表示文件为空或超出 8 MiB 上限；FAVORITE_AUDIO_CHANGED 表示副本 SHA256 不符。不改变收藏匹配、来源认证或缺失项失败计数策略。

同时修复诊断导出读取带 BOM 的旧日志时首条记录被丢弃的问题；新工作日志写入不带 BOM，旧日志导出兼容 BOM。合成隐私回归会保留该首条错误码，同时剔除其中注入的假私密字段。

## 用户复测

在电脑微信打开并播放失败的收藏，等待附件下载完成；回到工坊重新点击“收藏语音”创建新会话，再试听。若仍失败，用新包导出诊断，不要上传整个 workspace、真实数据库或录音。新统计用于区分缓存缺失、内容未匹配、回退无依据与匹配歧义。

这次诊断只确认上述读取阶段和错误提示，不视为真实账号全部收藏导出通过。
