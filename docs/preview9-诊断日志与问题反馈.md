# 诊断日志与问题反馈

2026-11-08，1.0.0-preview9。

软件主界面操作区增加“导出诊断包”，任务执行中也可导出当前记录。遇到问题后保存ZIP，连同大概发生时间、微信版本、操作步骤、错误截图一起发回即可；不必提供整个workspace或微信数据库。诊断包由用户选择保存位置，不自动上传。

## 记录什么

- 软件版本、Windows/.NET版本、64位状态、CPU线程数、引擎/模型/字表/关键DLL是否存在。
- 每次操作独立请求编号，贯穿WinForms、Python引擎和异常提示；界面失败时显示编号。
- 请求开始/退出、耗时、进程退出码，连接与数据库读取阶段、扫描命中数、重试和目录计数。
- 解码、导出、识别的阶段及成功/失败/取消数量。进度日志按阶段限频，逐条失败有异常类型和代码位置。
- Python异常类型、errno/Win32码，以及模块/函数/行号；原生依赖加载失败额外记录组件DLL名称、HRESULT和Win32码，进程崩溃记录退出码。

不记录请求正文、账号目录、会话或发送者、密钥、语音文件名、识别全文、异常中的自由文本消息或调用栈局部变量。完整错误仍可在本机界面和私人导出清单查看，需要时以截图补充。

## 范围和限制

结构化日志位于相对软件目录的 `workspace/diagnostics`。UI单文件约256KiB，保留当前加3份轮转；后台单文件约256KiB并保留一份轮转，启动新请求时清理旧记录，保留约32个后台日志文件。写盘失败尽力记录，不阻塞业务。

导出时仅接受UI/worker固定命名日志，最多40个、每个最多读取512KiB；逐行重做字段白名单。仅ZIP内environment.json、说明和logs，不打包原始数据库、DPAPI仓库、音频、索引、历史diagnostic.log或设置文件。旧日志留在本机，不静默删除。

这类隐私优先日志不能替代现场全部信息：不保存完整报错文本；突然断电或无写权限可能没有最新记录。请描述发生时间和步骤，并附错误截图。

## 验证

覆盖后台日志字段剔除、含隐私异常消息、轮转/保留数量、非法请求编号、写盘失败不影响业务；实际部署引擎制造失败，校验请求编号与诊断ZIP，并注入正文/旧日志验证不进入ZIP。正常导出与本地模型继续跑公开语音回归；缺DLL的独立组件检查结构化Win32错误。

本轮仅用合成账号/公开语音验证，不采集用户私人聊天或录音。
